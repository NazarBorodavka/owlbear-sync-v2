Map Auto-Zoom

Sets the map zoom so one grid square measures one token base (40mm) on the table. Changes the zoom only -- it never moves the map.

Works the zoom out arithmetically from the play-area size you calibrated in the tracker, this window's size and the scene's grid setting. Needs no camera and nothing on the table. It also checks its own assumption -- that the projected image fills the calibrated play area -- and warns you if the two axes disagree, which would mean the projector is not lined up with the play area. The result line below reports the cell size actually achieved across and down -- the two differ by the same skew, so you can see what the single chosen zoom really does in each direction.

Changing the zoom changes how much map the projector covers, so the stored Projector view no longer matches. If sync view is on it is re-read automatically; if not, it is cleared and needs re-pinning.

Position Anchor

What a token's measured millimetres are placed relative to. This is the setting that decides what happens to tokens when the map moves. It is stored per machine, not in the scene, because it describes which screen this computer is driving.

Places a token where its mini physically sits, as seen on the projector. Minis and tokens stay aligned no matter where you personally look, so you can pan and zoom your own view freely to scout ahead without anything on the table moving. While Owlbear's sync view is on, the projector mirrors you and this follows it live; switch sync off and both freeze on the view that was showing.

Treats the play-area origin as the map's own origin. Every client agrees on where a token is and nothing moves when anyone pans, but the minis only line up with the map while the projecting view sits exactly at its calibrated home position. Useful if you are not projecting at all.

Same as projector anchoring, but against your own live view rather than the projector's. Tokens follow whatever you are looking at, which means panning your view drags them across the map. Mainly useful when this panel is open on the projector machine itself.

Only one client should have this panel pushing positions. Two will fight over the same tokens.

Projector View

Which rectangle of the map the projector is throwing onto the table. Only used by Projector view anchoring above.

Stores what you are looking at right now as the projector's view. Normally unnecessary: it is captured automatically whenever you switch Owlbear's sync view off, which is the moment the projector stops following you and parks on what it was showing. Press this if you aligned the projector some other way, or if the stored view looks wrong. For an exact fit, press it from the projector machine -- sync view copies position and zoom between clients but not window size, so a differently-sized window covers a slightly different area. Stored in the scene, so it survives a reload.

Position Stability

How far a token has to move before the map is updated.

The camera measures each token to about 0.4mm typically, with occasional excursions up to ~2mm, so a token sitting untouched still twitches slightly. Anything under this threshold is treated as the token not having moved, measured against the last position actually accepted -- so small wobble cannot slowly accumulate into a drift, and one real movement past the threshold releases it immediately. 2mm is a good default: above the usual noise, and a twentieth of a token base. Set it to 0 to use every reading. Remembered in this browser.

Pause Position Sync

Stops writing token positions to the scene. Everything stays where it currently is until you switch it back off.

You probably do not need this. With Projector view anchoring and sync view off, panning your own view already moves nothing on the table, and the one jump when you press Sync View puts every token straight at its correct new spot. No pausing required.

It earns its place in two cases. If you leave sync view on permanently, the projector follows your every pan, so tokens slide across the map the whole time you are moving it -- pause first, move, then resume. The same applies to This screen anchoring, which tracks your live view by definition. In Map anchoring it does nothing useful, since panning never moves tokens there anyway.

Not remembered between reloads: left switched on, it would look exactly like a broken tracker.

Token Mapping

Which physical marker drives which token in the scene.

One row per marker the camera can currently see, named from the tracker dashboard if you have named it there. Pick the scene token each one should move. A marker whose name already matches a token in the scene is paired up automatically; that never overrides a choice you made by hand. Deleting a token from the scene clears its row. Saved into the scene itself, so it travels with the scene file and does not need redoing next session.
