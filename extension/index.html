Tracker Connection

What these do

Tracker URL — where the tracker's web service is, including the port; the same address its dashboard is on.

Auth — the dashboard's login as one user:password string.

Connect — saves both and starts polling. Press it again after changing either. Polling then continues on its own. Both fields are remembered in this browser.

The status bar at the top is green while the camera is connected (showing token count and frame rate), yellow if the camera dropped or position sync is paused, red if this panel cannot reach the tracker.

Map Auto-Zoom

What this does

Sets the zoom so one grid square measures one token base (40mm) on the table. Changes the zoom only — it never moves the map.

Worked out arithmetically from the play-area size you calibrated in the tracker, this window's size and the scene's grid setting. No camera needed and nothing on the table.

It also checks its own assumption — that the projected image fills the calibrated play area — and warns if the two axes disagree, which would mean the projector is not lined up with the play area. The result line reports the cell size actually achieved across and down; those differ by the same skew, so you can see what one chosen zoom really does in each direction.

Changing the zoom changes how much map the projector covers, so a stored projector view no longer matches. If sync view is on it is re-read automatically; if not, it is cleared and recaptured the next time you sync.

Position Anchor

What these do

What a token's measured millimetres are placed relative to. This decides what happens to tokens when the map moves. Stored per machine, not in the scene, since it describes which screen this computer drives.

Projector view — places a token where its mini physically sits, as seen on the projector. Minis and tokens stay aligned wherever you personally look, so you can pan and zoom your own view freely to scout ahead without anything on the table moving. While sync view is on the projector mirrors you and this follows live; switch sync off and both freeze on that view.

Map — treats the play-area origin as the map's origin. Every client agrees and nothing moves when anyone pans, but minis only line up while the projecting view sits exactly at its calibrated home. Useful if you are not projecting.

This screen — as projector view, but against your own live view, so panning drags tokens across the map. Mainly for when this panel is open on the projector machine itself.

Only one client should have this panel pushing positions. Two will fight over the same tokens.

Projector View

What this is

Which rectangle of the map the projector throws onto the table. Only used by Projector view anchoring.

Captured automatically: kept up to date the whole time Owlbear's sync view is on, and retained when you switch sync off — the moment the projector stops following you and parks on what it was showing. Switching sync on once is all that is needed to establish it. Stored in the scene, so it survives a reload.

Sync view copies position and zoom between clients but not window size, so if the projector window is a different pixel size from this one it covers a slightly different area. For an exact fit, run this panel on the projector machine.

Position Stability

What this does

How far a token must move before the map is updated. The camera measures each token to about 0.4mm typically, with occasional excursions to ~2mm, so an untouched token still twitches slightly.

Anything under this threshold counts as not having moved, measured against the last position actually accepted — so small wobble cannot slowly accumulate into a drift, and one real movement past the threshold releases it immediately.

2mm is a good default: above the usual noise, and a twentieth of a token base. Set it to 0 to use every reading. Remembered in this browser.

Pause Position Sync

When you need this

Stops writing token positions to the scene. Everything stays where it is until you switch it back off.

Usually unnecessary. With projector anchoring and sync view off, panning your own view already moves nothing on the table, and the single jump when you press Sync View puts every token straight at its correct new spot.

It earns its place if you leave sync view on permanently — then the projector follows your every pan, so tokens slide across the map the whole time you are moving it; pause, move, then resume. Same for This screen anchoring, which tracks your live view by definition. In Map anchoring it does nothing useful, since panning never moves tokens there.

Not remembered between reloads: left switched on, it would look exactly like a broken tracker.

Token Mapping

How this works

One row per marker the camera can currently see, named from the tracker dashboard if you have named it there. Pick the scene token each should move.

A marker whose name already matches a scene token is paired up automatically; that never overrides a choice you made by hand. Deleting a token from the scene clears its row. Saved into the scene itself, so it travels with the scene file and does not need redoing next session.

Camera setup, calibration, the video feed and the timing readout are all in the tracker dashboard, not in this panel.
